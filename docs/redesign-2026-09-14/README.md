## Decisions

1. **Green token `#14804a`, hover `#0f6b3d`** (not the suggested `#0b6b3a`). White text on `#14804a` = 4.98:1 (AA), green text on white = 4.98:1, and the button against the navy hero `#0f2440` = 3.13:1, which satisfies WCAG 1.4.11 non-text contrast (3:1). `#0b6b3a` gives 6.6:1 for text but only 2.4:1 against the navy hero, so the primary button would have failed on the hero and CTA bands. All eleven token pairs are computed by `verify-agency.mjs` (`qa/verify-agency.json`): 4.98 / 6.58 / 4.98 / 3.13 / 15.59 / 11.33 / 9.33 / 5.56 / 5.13 / 4.91 / 10.94.
2. **Navy `#0f2440`** for hero and CTA bands (Codex’s candidate used `#112f50`; the darker value keeps the green button at ≥ 3:1).
3. **Hero image** is the SFC South Shore explorer (real shipped work on a NOAA-hosted aerial, already approved for the site) rather than the headshot Codex’s candidate used: an agency hero should show work; the principal appears in the header mark, the “A practice, led hands-on” strip and About.
4. **Information architecture**: Services · Work · Lab · Writing · About + **Let’s talk**; utility Resumes · Clients. Work, Services and Lab carry dropdowns (CSS `:hover`/`:focus-within`, keyboard reachable; the mobile `<details>` menu lists every link flat). `/work/` stays the complete React collection page (all 17 case studies, filters, complete HTML) restyled by tokens; `/case-studies/` also remains. Only `/services/` was added — 58 published URLs, 4 placeholders and 404 unchanged.
5. **Copy pack adopted** (`content-studio/drafts/2026-09-14-agency-copy-pack.md`): §(b) lifecycle lines verbatim; §(c) objectives bodies for tiles 1, 3 and 4 (tile titles keep the brief’s four visitor questions); §(d) Services stage copy, evidence lines, process and FAQ; §(e) industries (five with evidence — “professional services” from the brief has no case-study evidence and was dropped; “small business” is folded into “Travel, recreation & local services” as the pack proposed); §(h) meta titles and descriptions. Edits: the FAQ answer “Is this a team or one person?” drops the pack’s trailing internal note (“nothing here claims a specific team size”); a sixth question on working alongside in-house teams is added (sourced from the case-study data: cross-functional Apple delivery, Yext engineering); the resume description names the four on-page labels (Search Direction, AI Search Engineering, Product Management, Organic Systems Architecture) instead of the README labels, so it matches what the page shows. Not adopted: §(a) hero headline options (the brief’s positioning sentence is used; see open decisions), §(f) CTA variants other than #1, §(g) About opener (About content is unchanged by order).
6. **Marquee label** uses the content worker’s `label` (“Experience across”), the approved string from the design-review proposal; the key line under it states that employers, clients and independent projects are mixed and each entry is labelled.
7. **Smooth scrolling removed** from the shell CSS (`html{scroll-behavior:smooth}` made the headless capture’s lazy-image wait hang for the 180 s protocol timeout; the QA script also now scrolls with `behavior: 'instant'` and caps the image wait at 10 s).
8. **Resume dialog trigger**: the header/mobile **Resumes** links carry `data-resume-open` (the archived header’s “Download Resume” button no longer exists), so the native `<dialog>` chooser still opens on every page and falls back to `/resume/` without JavaScript.
